1
📝 User Input
User enters a text prompt, e.g. "A cat sitting on a windowsill at sunset"
2
🔤 Tokenize & Embed Understanding Expert
The text is tokenized by Qwen2Tokenizer, wrapped with special tokens, and embedded via embed_tokens(). Then run through all LLM layers using the understanding expert to build the KV cache.
"A cat sitting on a windowsill"
  → tokenizer.encode() → [<bos>, 32, 8415, ..., <eos>]   // 10 tokens
  → embed_tokens() → [10, 3584]   // embed to hidden dim
  → forward_cache_update_text() → KV cache updated
KV Cache:
text: 10 tokens
3
🔀 Prepare 3 CFG Contexts
Three separate KV caches are prepared for Classifier-Free Guidance. Each stores a different subset of context. During the denoising loop, the model will run 3 forward passes per step — one against each cache.
gen_context      = text KV   // full context → main prediction
cfg_text_context = empty     // no text → "what would model do without the prompt?"
cfg_img_context  = text KV   // same as full (no input image in T2I)
4
🎲 Initialize Noise Latent
A random Gaussian noise tensor is created in the VAE latent space, sized to produce the target image. The latent is "patchified" — grouped into 2×2 patches.
Target image: 1024 × 1024 pixels
→ latent_downsample = vae_down(8) × patch(2) = 16
→ grid: 64 × 64 = 4096 latent tokens
→ each token: 2² × 16ch = 64 dims
→ packed_init_noises: [4096, 64] ~ N(0, 1)
5
🔄 Denoising Loop × 49 steps Generation Expert
The core generation loop. At each step, the noisy latent is projected into the LLM, processed, and a velocity is predicted. The velocity points from data toward noise, so we subtract it to move from noise toward the clean image.
// For each timestep t = 1.0 → 0.02 (49 steps):

① Project latent into LLM space:
  x_t [4096, 64] → vae2llm → [4096, 3584]
    + time_embedder(t)   // scalar t → [3584] via sinusoidal + MLP
    + latent_pos_embed   // 2D sincos position for 64×64 grid

② Assemble sequence:
  [<start_img>, latent₁...latent₄₀₉₆, <end_img>]

③ Run LLM (3 passes for CFG):
  Pass 1: sequence + gen_context KV       → v_t         // with text
  Pass 2: sequence + cfg_text_context KV → cfg_text_v_t // without text
  // Latent tokens → generation expert (q/k/v_moe_gen, mlp_moe_gen)
  // Bracket tokens → understanding expert (q/k/v_proj, mlp)

④ Read velocity:
  output → llm2vae → v_t [4096, 64]

⑤ CFG:
  v_guided = cfg_text_v_t + 4.0 × (v_t − cfg_text_v_t)
  v_final  = v_guided × renorm_scale

⑥ Update:
  x_t = x_t − v_final × dt   // move from noise toward clean image
Each step processes:
text (KV)
+
4096 latent (query)
6
🖼️ VAE Decode
The denoised latent is unpatchified back to spatial form, then decoded by the VAE into pixel space.
x_final [4096, 64]
  → reshape to [1, 64, 64, 2, 2, 16]
  → einsum "nhwpqc→nchpwq" → [1, 16, 128, 128]
  → vae_model.decode() → [1, 3, 1024, 1024]
  → denormalize (×0.5+0.5) → clamp [0,1] → uint8
7
✅ Output
A 1024 × 1024 PIL Image is returned and displayed in the Gradio UI.
1
🖼️ User Input
User uploads an image (e.g. a meme, 800×600) and asks a question: "What's funny about this?"
2
👁️ SigLIP ViT Encode Understanding Expert
The image is patchified and encoded by SigLIP vision transformer to extract semantic features. Only ViT is used (no VAE) because we need to understand, not generate.
Image 800×600 → resize to 980×736 (ViT transform)
  → patchify(patch=14) → [3640, 588]   // 70×52 patches, 14²×3 dims
  → SiglipVisionModel:
      patch_embedding → [3640, 1152]
      + 2D RoPE (cos_h, sin_h, cos_w, sin_w)
      × 27 encoder layers (Flash Attention, bidirectional)
      post_layernorm → [3640, 1152]
  → connector MLP → [3640, 3584]   // project to LLM dim
  → + vit_pos_embed (2D sincos)
KV Cache:
ViT: 3640 + 2 bracket = 3642 tokens
3
🔤 Tokenize Question Understanding Expert
The question text is tokenized and cached. These tokens attend to the already-cached image tokens.
"What's funny about this?"
  → tokenize → [<bos>, What, 's, funny, about, this, ?, <eos>]   // ~9 tokens
  → embed_tokens → [9, 3584]
  → LLM forward (attend to 3642 image KV + 9 self) → cache updated
KV Cache:
ViT: 3642 tokens
text: 9 tokens
4
💬 Autoregressive Text Generation Understanding Expert
Starting from <bos>, the model generates one token at a time. Each new token attends to the full KV cache (image + question + all previously generated tokens).
// Repeat until <eos> or max_length:

token → embed_tokens → [1, 3584]
  → LLM forward (mode="und", attend to all 3651+ cached tokens)
  → lm_head → logits [151665]   // vocab size
  → argmax (greedy) or sample(temperature=0.3)
  → next token ID → append to KV cache → repeat

// Each generated token: 1 embed + 1 LLM forward + 1 lm_head
// KV cache grows by 1 each step
Growing cache:
image (3642)
question (9)
generated (1, 2, 3...)
5
✅ Output
The generated token IDs are decoded by the tokenizer. Special tokens (<|im_start|>, <|im_end|>) are stripped.
token_ids → tokenizer.decode() → "The humor in this meme comes from the contrast between..."
1
🖼️ + 📝 User Input
User uploads an image (e.g. a photo of a woman, 1024×768) and provides an edit instruction: "She boards a modern subway, wearing the same clothes"
2
🟣 VAE Encode Input Image Generation Expert
The input image is encoded by the VAE into latent space, patchified, projected, and cached. The generation expert processes VAE latent tokens (while bracket tokens use the understanding expert).
Image 1024×768
  → vae_model.encode() → latent [1, 16, 128, 96]
  → patchify (2×2) → [64×48 = 3072, 64]
  → vae2llm + time_embed(t=0) + pos_embed → [3072, 3584]
  → LLM forward (mode="gen") → cache 3074 tokens (3072 + 2 brackets)
KV Cache:
VAE latent: 3074 tokens
3
👁️ SigLIP ViT Encode Same Image Understanding Expert
The same image is also encoded by SigLIP ViT for semantic understanding. This gives the model both pixel-level (VAE) and semantic-level (ViT) representations of the input.
Same image 1024×768 (ViT transform → 980×736)
  → SiglipVisionModel → [3640, 1152]
  → connector MLP → [3640, 3584]
  → LLM forward (mode="und") → cache 3642 tokens
KV Cache:
VAE: 3074
ViT: 3642
4
🔤 Tokenize Edit Instruction Understanding Expert
The edit instruction is tokenized and cached. These tokens can attend to both VAE and ViT image tokens.
"She boards a modern subway, wearing the same clothes"
  → tokenize → ~14 tokens
  → LLM forward (attend to all 6716 cached tokens) → cache updated
KV Cache:
VAE: 3074
ViT: 3642
text: 14
5
🔀 Prepare 3 CFG Contexts
The three contexts are snapshot at different points to enable dual CFG — guiding toward both text compliance and image preservation.
gen_context      = VAE + ViT + text KV   // full context
cfg_text_context = VAE + ViT KV          // image but NO text → "preserve the image"
cfg_img_context  = text KV only           // text but NO image → "follow the instruction"
6
🔄 Denoising Loop × 49 steps — Full 3-Pass CFG Generation Expert
Same denoising loop as T2I, but now all three CFG passes are active since cfg_img_scale=2.0. The dual guidance steers the output to follow the instruction while preserving the input image.
// For each timestep t = 1.0 → 0.02:

Three LLM forward passes per step:
  Pass 1: noise + full KV (img+text)  → v_t           // conditioned on everything
  Pass 2: noise + text-cfg KV (img)   → cfg_text_v_t  // no instruction text
  Pass 3: noise + img-cfg KV (text)   → cfg_img_v_t   // no image

Dual CFG composition:
  v_text  = cfg_text_v_t + 4.0 × (v_t − cfg_text_v_t)     // follow text
  v_final = cfg_img_v_t  + 2.0 × (v_text − cfg_img_v_t)   // preserve image
  v_final = v_final × renorm("text_channel")

Update: x_t = x_t − v_final × dt
7
🖼️ VAE Decode → Edited Image
The denoised latent is unpatchified and decoded back to pixel space — producing the edited image at the same resolution as the input.
x_final [3072, 64]
  → reshape → [1, 16, 96, 128]
  → vae_model.decode() → [1, 3, 768, 1024]
  → PIL Image 1024×768
8
✅ Output
The edited image is returned — showing the woman in a subway, wearing the same clothes, at the original resolution. The dual-encoder approach (VAE for pixel fidelity + ViT for semantic understanding) enables intelligent editing.
